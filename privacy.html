Privacy Policy

Draft updated November 15, 2026

This draft describes data flows for the Sona website and app. The legal basis for each activity, remaining retention details, and international transfer safeguards still need confirmation before publication.

1. Who is responsible

Braian Gapur operates Sona and is responsible for the processing described here. For privacy questions or requests, email support@sona-ade.com. See the Impressum for operator information.

2. Website visits and downloads

GitHub Pages hosts this website. GitHub records visitors' IP addresses for security purposes.

The website loads fonts from Google Fonts. Your browser connects to Google's font servers and sends network request information, including your IP address. See Google Fonts' privacy information.

Installers and checksums are hosted on Hetzner Object Storage. Following a download link sends a request to that service, including your IP address and browser request information. See Hetzner's privacy policy.

The website reads browser platform information locally to suggest a download. When you click an installer link, it sends a download_clicked event to PostHog's EU ingestion service with the selected platform, installer architecture, filename, and a website source label. Each event uses a new random identifier. These counts measure clicks, not completed downloads or unique visitors.

Website download tracking does not set cookies, save analytics identifiers in browser storage, or record page views or sessions. It respects the browser's Do Not Track and Global Privacy Control signals. PostHog receives the network request, including your IP address, but our project setting removes IP addresses from stored events and the event disables location inference and person profile creation. Blocked analytics does not prevent downloads. App analytics and crash reporting described below apply when you run Sona.

3. Local work and connected services

Sona stores workflow state locally. Connected agents and integrations may send information to their providers according to their settings and policies. Review those policies before granting access to confidential code or data.

Local workflow records are separate from telemetry reports. Enabling telemetry does not make all local data public, but the selected level determines which fields Sona sends to the telemetry service.

4. PostHog and app usage data

We use PostHog for telemetry and app usage analytics to understand how people use Sona and diagnose problems. Depending on your telemetry level, reports include workflow activity, outcomes, timings, diagnostic counters, and version information. A random installation identifier links telemetry events from the same installation. The default level, named anonymous, limits free-text fields and hashes selected identifiers. The full level also includes the text and path fields listed in the telemetry documentation. The default hosted telemetry relay forwards these events to PostHog.

The hosted relay runs on Cloudflare Workers. It receives telemetry requests and forwards their event payloads to PostHog. It disables PostHog location inference and forwards the relay's network address rather than your device's IP address. A persistent installation identifier can still link activity over time, so the level name anonymous does not mean every event is unidentifiable under data protection law.

5. Sentry crash and session reports

The desktop app uses Sentry for crash reporting and release health, hosted in Sentry's Germany region. Error reports contain exception types, stack-frame source locations, severity, SDK information, and release and environment metadata. They omit exception messages, prompts, source snippets, absolute source paths, and user details. Session reports include a random session identifier, status, error counts, timestamps, and duration. These reports help us diagnose failures and measure app stability.

Sona's report payload replaces the IP address with an unspecified address and omits persistent user and installation identifiers. Network connections still reach Sentry's infrastructure. Crash reporting is separate from the PostHog event pipeline.

6. Collection controls and local queues

Crash and session reporting use the same restricted payload at both the anonymous and full telemetry levels. Setting telemetry to off disables telemetry uploads and suppresses new Sentry reports. Some diagnostic events still queue locally while telemetry is off and may upload if you later enable it. Disabling reporting does not recall data already submitted.

To disable uploads and clear pending telemetry, run sona telemetry disable. You can also choose off during installation. The default telemetry level is anonymous. Both anonymous and full allow uploads. Some diagnostic events can queue again locally while off; run the disable command again before re-enabling if you want to clear that queue.

7. Support correspondence

If you email support, we receive your email address, the message, and any attachments you send. We use that information to respond and investigate the issue. Zoho Mail handles our support mailbox. Avoid sending credentials or confidential code unless needed for your request.

8. Retention and processing arrangements

Sentry error events follow its free Developer plan's 30-day retention period. Session statistics, issue summaries, and provider backups may have separate retention periods; the error-event period does not describe every record Sentry stores. See Sentry's error retention guidance.

PostHog event retention follows the seven-year default for our paid plan, which began before November 5, 2026. Expired events may remain stored until PostHog deletes them in batches, so expiry is not a promise of immediate deletion. See PostHog's retention policy. Sona's telemetry relay does not enforce a remote deletion period. Local telemetry queues and workflow records have separate deletion controls described in the documentation above.

Before publication, this policy must state the applicable legal basis and retention period or criteria for each processing activity, including support correspondence. Provider processing arrangements and any international transfers also need confirmation. A hosting region alone does not establish where every provider or subprocessor handles data.

9. Your rights

Subject to the conditions in data protection law, you may request access, correction, deletion, restriction, or portability of personal data. You may object to processing based on legitimate interests. Where processing relies on consent, you may withdraw it without affecting the lawfulness of earlier processing.

Email support@sona-ade.com to make a request. Installation-linked telemetry may require the installation identifier to locate the relevant records. Do not send passwords or API keys.

You may complain to a data protection supervisory authority, including the North Rhine-Westphalia authority or the authority where you live or work.
